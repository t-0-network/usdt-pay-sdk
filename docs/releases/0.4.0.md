# 0.4.0

t-0 now tells an LP when the issuer's USDt settlement to its wallet is confirmed,
through a new callback, `LpCallbackService.UsdtSettlementCompleted`. LPs must
implement it, in the same change as the upgrade: on Python a missing method can stop
`ExecuteQuote` too. Acquirers and issuers have nothing to change.

## What an LP implements

t-0 calls `UsdtSettlementCompleted` once it has verified on-chain that the issuer's
USDt reached your registered wallet. The transfer itself carries no reference, so
this is how you match the credit to your executions. The request carries
`settlementId`, `settlementAmount`, `settledExecutionIds`, `settledAt` and the
on-chain `settlement` details.

- It arrives for a confirmed transfer only. A failed verdict, or no verdict at all,
  sends you nothing, so treat a transfer as unconfirmed until this arrives.
- `settledExecutionIds` is ascending and may list an execution you rejected or have
  not answered or received yet, so an id you do not recognize is not an error.
- Delivery is at least once, keyed on `settlementId`. A repeat must answer success
  without counting the transfer twice.
- It does not gate `FiatSettlementSent`: you may wire the fiat and report it first.

An LP that does not implement the callback does not receive these notices: t-0
retries each one for a limited time, then stops. Settlements t-0 confirmed before it
started sending this get no notice.

## Migration from 0.3.1

### Node

`ServiceImpl<typeof LpCallbackService>` now requires `usdtSettlementCompleted`, so a
handler without it does not compile (TS2741). The starter's `^0.3.1` pin does not
admit 0.4.0: an existing project moves only when you change the pin.

### Python

`LpCallbackService` and `LpCallbackServiceSync` gain `usdt_settlement_completed`. A
class that inherits from them answers `UNIMPLEMENTED` on this call until you override
it.

A class that does not inherit from them breaks the whole service until the method
exists. `LpCallbackServiceWSGIApplication` raises `AttributeError` when it is built.
`LpCallbackServiceASGIApplication` builds and, under uvicorn's default settings,
starts, then answers every call on that service with a 500, `ExecuteQuote` included.

### Go

`lpconnect.LpCallbackServiceHandler` gains `UsdtSettlementCompleted`, so a handler
without it does not compile. One that embeds `UnimplementedLpCallbackServiceHandler`
compiles and answers `Unimplemented` until you add the method.

### Java

Override `usdtSettlementCompleted` on your
`LpCallbackServiceGrpc.LpCallbackServiceImplBase`.

## Starters and CLI

New LP scaffolds (`usdt-pay init --lang=node --role=lp my-lp`) carry the callback. It
logs the call and answers success; Phase 5 of the starter README and the TODOs in
`src/handler.ts` say what to add. Existing scaffolded projects keep their own starter
code; update it explicitly.

See [PR #133](https://github.com/t-0-network/usdt-pay-sdk/pull/133) for the contract
and starter changes.
