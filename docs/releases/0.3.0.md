# 0.3.0

This release upgrades provider-sdk to **1.3.1** and includes the SDK and starter
changes merged since 0.2.9. Upgrade client construction before deploying.

## Migration from 0.2.9

### Required pay API endpoint

Pass the pay API base URL explicitly, for example
`https://pay-api-sandbox.t-0.network`. Missing or empty endpoints fail at
client construction; there is no fallback to `api.t-0.network`. Node rejects
`undefined`, `null` and `""`; Python rejects `None` and `""` with `ValueError`,
and omitting the required `base_url` keyword raises `TypeError`. Go returns an
error for `""`; Java rejects `null` and `""`.

Starters resolve `TZERO_ENDPOINT` to the sandbox URL when unset and always pass
it to the client.

### Node

Change the argument order from `createClient(endpoint, signer, service)` to
`createClient(signer, baseUrl, service)`:

```ts
import { createClient, IssuerService } from "@t-0/usdt-pay-sdk";

const t0 = createClient(privateKeyHex, baseUrl, IssuerService);
```

Check every call: swapping two string arguments still type-checks.

- `createRequestDecoder` now takes only `{ networkPublicKey }`; remove other
  options. The pay registry and SDK version are supplied by the wrapper.
- `DEFAULT_TOLERANCE_MS` and `parsePublicKey` are removed from the exports.
  Signature timestamps use provider-sdk's fixed window.
- `@connectrpc/connect` is pinned to `2.1.2`, matching provider-sdk. Import
  `ConnectError`, `Code` and `ServiceImpl` from `@t-0/usdt-pay-sdk` to use the same
  bindings as the transport.
- The supported Node range is `^20.19.0 || >=22.12.0`.

### Python

Replace `create_client(endpoint, signer, client_class, timeout=...)` with
`create_client(signer, client_class, base_url=...)`. The same change applies to
`create_client_sync`:

```python
from t0_usdt_pay_sdk import create_client
from t0_usdt_pay_sdk.api.tzero.v1.pay.acquirer.acquirer_connect import AcquirerServiceClient

t0 = create_client(private_key_hex, AcquirerServiceClient, base_url=base_url)
```

- Remove `timeout=` from client construction. Set `timeout_ms=` on an individual
  RPC when overriding the provider-sdk deadline.
- Remove `logger=` from `create_asgi_app` and `create_wsgi_app`.
- Import `signature_verification_middleware` from
  `t0_provider_sdk.provider.middleware`, and
  `signature_verification_middleware_wsgi` from
  `t0_provider_sdk.provider.middleware_wsgi`; they are no longer re-exported by
  the pay SDK.
- The Python starter uses ASGI; its `acquirer.wsgi` entry and sync helpers are
  removed. The SDK retains `create_wsgi_app`, `create_client_sync` and
  `handler_sync` for integrations that use sync code.

### Go

- `CreateClient(baseURL, privateKeyHex, newClient)` no longer accepts client
  options. For custom options or an HSM/KMS signer, use provider-sdk's
  `network.NewServiceClient` with `network.WithBaseURL` and
  `network.WithSignatureFunction` directly. `CreateClientWithSigner` is removed.
- Empty endpoints and network keys return provider-sdk's errors.
- In starter code, use `Outcome.Accepted()` for the accepted payload and handle
  the error returned by `DecimalFromString`.

### Java

- Use `UsdtPayClient.create(baseUrl, signer, stubFactory)` for a signed blocking
  client. Custom client options remain available through provider-sdk directly.
- `CallDeadline` and `UsdtPayServer.Builder.withMaxInboundMessageSize` are
  removed. Override a call's deadline with `t0.stub(30, TimeUnit.SECONDS)`.
- Recompile code using provider-sdk's `BlockingNetworkClient.create`: its
  three-argument overload takes `DigestSigner`.
- In starter code, use `Outcome.accepted()` for the accepted payload;
  `Rejected.failingIds` is removed.

## SDK behavior and additions

- Calls use provider-sdk's default deadlines. Python requests are no longer
  gzipped; Go and Python clients no longer follow redirects.
- Node servers handle unsupported streaming RPCs without the crash affecting
  0.2.9. Java validates responses against the contract. Python and Java servers
  accept request bodies up to 10 MiB.
- Node exports the SDK version, validation helpers, body-size limit and Connect
  error/types from the root. The `/crypto` subpath also exports the pay messages,
  services, registry, SDK version and `publicKeyFromPrivateKey`, while preserving
  isolation from `node:http` and the Connect Node adapter.
- Python exports Connect errors/codes, signature header names,
  `NetworkPublicKeyRequiredError`, `DEFAULT_MAX_BODY_SIZE`, `VerifySignatureFn`,
  `ASGIApp` and `WSGIApp` at the top level.
- Signed-response tests exercise the pay contract's custom rules in every SDK.
  Request-side custom-rule tests cover Go and Node.

## Starters and CLI

New scaffolds use the updated SDKs, consistent configuration errors, graceful
signal handling and non-root Docker users. Network keys are checked during
server setup. Network failures are logged without stack traces. Existing
scaffolded projects keep their own starter code; update it explicitly if needed.

See [PR #121](https://github.com/t-0-network/usdt-pay-sdk/pull/121) for the API and
starter changes and [provider-sdk 1.3.1](https://github.com/t-0-network/provider-sdk/releases/tag/v1.3.1)
for the upstream endpoint change.
